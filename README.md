# 🍽 MealLog — 食事カロリー記録PWA

スマホで写真を撮る(またはテキスト入力する)だけで、AIが食事のカロリー・栄養素を推定して記録するWebアプリです。**サーバー費用・API費用は一切かかりません。**

- 📷 写真 or 💬 テキスト → Gemini API(無料枠)でカロリー・PFC自動推定
- 📊 その日のカロリーとPFC(たんぱく質・脂質・炭水化物)を目標との対比バーで表示
- 📅 履歴は日付を選んでその日のカロリー/PFCを確認
- 🍚 テンプレート — 白米などの定番品目をワンタップ+分量選択で記録(AI不使用・毎回同じ値)
- 💡 食事履歴から好みを分析して、次に食べるものの候補を提案
- 📱 PWA対応 — スマホのホーム画面に追加してアプリのように使える
- ☁️ GitHubプライベートリポジトリに記録を自動同期(機種変更でもデータが残る)
- 📤 Markdown / JSON / CSV でエクスポート — そのままChatGPTやClaude等のLLMに渡して食事分析に使える

## 仕組み

```
スマホ(PWA)
   ├─ 写真/テキスト → Gemini API 無料枠 → カロリー推定
   ├─ IndexedDB(端末内保存・オフライン対応)
   └─ GitHub API → プライベートリポジトリに月別 JSON/Markdown を自動コミット
```

APIキーやトークンは端末のブラウザ内(localStorage)にのみ保存され、外部に送信されません(Gemini/GitHubの公式API呼び出しを除く)。

## カロリー / PFC の表示

記録画面の先頭に、その日の合計カロリーとPFCを目標との対比で表示します。履歴画面では日付を選ぶと、同じカードでその日の実績を確認できます。

- **PFCの目標値**: 設定 →「🎯 目標」で目標カロリーとPFC比率(既定 P20% / F25% / C55%)を指定すると、目標g を自動計算します(P・Cは4kcal/g、Fは9kcal/g換算)。g を直接指定したい場合は下段の入力欄に入れると、そちらが優先されます。
- 目標カロリーが未設定のときはバーを出さず、実績値のみを表示します。

## 履歴画面

日付を選択して、その日のカロリー・PFCと食事一覧を表示します(全期間を1ページに並べる形式は廃止しました)。

- **選べる範囲**: この端末のIndexedDBに残っている記録の範囲(最古の記録日 〜 今日)。範囲は開くたびにデータから算出するため、古い記録が消えれば選択できる範囲も自動的に狭まります。画面上部に現在の範囲を表示します。
- **移動方法**: 日付ピッカー / 前後ボタン(記録のある日へジャンプ)/ 棒グラフのタップ。
- グラフは選択日を右端とする直近14日で、選択中の日を強調表示します。

## テンプレート機能

よく食べる品目を「テンプレート」として登録しておくと、記録画面のチップをタップ → 分量を選ぶだけで記録できます。栄養値は登録済みの基準値から決定的に計算されるため、AI推定と違って毎回同じ値になります。

- **分量の指定方法は2通り**
  - **100gあたり**: 基準栄養値(100gあたり)+刻み幅を登録。例: 白米は50g刻みで 150g → 234kcal、200g → 312kcal
  - **1単位あたり**: 1個/1本あたりの栄養値を登録し、個数で指定。刻み幅も指定でき、果物は0.5刻み。例: りんご0.5個 → 67kcal、卵2個 → 142kcal
- **初期登録**: 米・果物・卵の12品目
  - 米(100gあたり・50g刻み): 白米・玄米ごはん・麦ごはん
  - 果物: バナナ・りんご・みかん・梨・桃・キウイ(1個/1本あたり・0.5刻み)、いちご・ぶどう(100gあたり)
  - 卵(1個あたり)
- 栄養値は**日本食品標準成分表2020年版(八訂)/増補2023年**に基づきます(成分表未収載の麦ごはんのみ、精白米めし7:押麦めし3の計算値)。果物の1個あたりの値は「100gあたりの値 × 可食部の目安重量」で換算しています
- **追加・編集・削除**: 設定 → 食品テンプレート から。分類(米/果物/卵/その他)も指定できます。エディタの品目行の ☆ ボタンで、入力中の品目をそのままテンプレート化もできます
- **端末間同期**: GitHub同期を設定していれば `templates.json` としてデータリポジトリに保存され、複数端末で共有されます(削除も伝播します)

## 提案機能

「提案」タブで、これまでの記録から好みを分析して食事の候補を出します。

- **好みの根拠**: 直近90日の品目別頻度、時間帯ごとの傾向、1食あたりの平均カロリー
- **重複回避**: 直近3日に食べたものは候補から外れます
- **カロリー考慮**: 目標カロリーを設定していれば、今日の残り分に収まる候補を優先します
- **条件指定**: おまかせ / 外食 / 自炊の切り替えと、「さっぱりしたもの」などの気分入力
- 候補の「これにする」を押すと、記録画面にプリフィルされた状態で移動します

集計はすべて端末内で行われます。「よく食べているもの」ランキングはAPIキーなしでも表示されます。

## セットアップ

### 1. Gemini APIキーの取得(無料・クレカ不要)

1. [Google AI Studio](https://aistudio.google.com/apikey) にGoogleアカウントでログイン
2. 「APIキーを作成」をタップしてキーをコピー
3. アプリの **設定 → AI解析(Gemini)** にキーを貼り付けて「設定を保存」

> 無料枠には1日あたりのリクエスト回数上限がありますが、食事記録の用途(1日数回)なら十分です。課金設定をしない限り料金は発生しません。

### 2. GitHub同期の設定(任意・推奨)

1. データ保存用の **プライベートリポジトリ** を作成(例: `meal-log-data`)
2. [Fine-grained personal access token](https://github.com/settings/personal-access-tokens/new) を発行
   - Repository access: **Only select repositories** → `meal-log-data` のみ
   - Permissions: **Contents → Read and write** のみ
3. アプリの **設定 → GitHub同期** に `ユーザー名/meal-log-data` とトークンを入力して保存

記録するたびに `meals/YYYY-MM.json`(構造化データ)と `meals/YYYY-MM.md`(Markdownテーブル)が自動コミットされます。テンプレートはリポジトリ直下の `templates.json` に同期されます。

### 3. スマホのホーム画面に追加

1. スマホのブラウザでアプリのURL(GitHub PagesのURL)を開く
2. **Android (Chrome)**: メニュー → 「ホーム画面に追加」
3. **iPhone (Safari)**: 共有ボタン → 「ホーム画面に追加」

## AIでの食事分析

エクスポートしたMarkdownや、データリポジトリの `meals/YYYY-MM.md` をそのままLLMに貼り付けて:

> この食事記録を分析して、栄養バランスの問題点と改善案を教えて

のように使えます。
